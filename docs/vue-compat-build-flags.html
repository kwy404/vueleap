@vue/compat build flags explained

@vue/compat, the Vue 3 migration build, is a build of Vue 3 that can emulate Vue 2 behavior feature by feature. Each feature has a flag. Knowing which flags your code needs tells you exactly what is left to migrate.

Updated 2026-10-12

Runtime flags and compiler flags

Runtime flags (such as GLOBAL_MOUNT or INSTANCE_EVENT_EMITTER) are set with configureCompat(), globally or per component with the compatConfig option. Compiler flags (the COMPILER_ ones, such as COMPILER_FILTERS) change how templates compile and are set in the build tool.

Get the minimal flags for your project

vueleap maps every finding to its flag and prints the smallest configuration that keeps your app running, split into runtime and compiler parts:

npx vueleap --compat

As you fix findings, rerun the command: flags disappear from the output, and you can delete them from your config. When nothing is left, remove @vue/compat.

Frequently asked questions

Should I use @vue/compat?

Use it for medium and large apps that cannot be migrated in one go: it lets the app run on Vue 3 while Vue 2 code is still being converted. It is a migration aid, so plan to remove it. Small apps are often faster to migrate directly.

What is the difference between configureCompat and compatConfig?

configureCompat() sets runtime flags in the browser. Template flags (the COMPILER_ ones) are applied when templates are compiled, so they go in compilerOptions.compatConfig of your build tool plugin.

What does MODE 3 mean?

With MODE: 3, every feature behaves like Vue 3 unless its flag is set to true. With the default MODE: 2, everything behaves like Vue 2 unless its flag is set to false.
